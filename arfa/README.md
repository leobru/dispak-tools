# АРФА: служебные программы архивной системы

БЮСТ (распределение архивного пространства по бюджетам) восстановлен:
Паскаль-часть — `bust.pas`, процедуры PARAM, RDCAT и USED на Мадлене — в
`bust.pre`. Сборка `./buildovl.sh bust.pas БЮСТ bust.bin` (`make bust.bin`
извлекает оригинал из 2113/1704) даёт образ, который отличается от
оригинала одним словом 0776 заглушки оверлея. Его строит OVERLAY из
ячейки 046 монитора: оригинал записан под ЗС5, сборка идёт под ЗСХ.

СТАРФА (статистика архива по каталогу, оверлей STAT на 2113/1710-1717)
восстановлена так же: `starfa.pas` и модули на Мадлене в `starfa.pre`: ТЕРМ (терминал, ключ
администратора) и ПЕРЕКОД (пустая процедура, которую программа
вызывает после начальных присваиваний, с начальными значениями таблиц
перекодировки ГОСТИСО и ИСОГОСТ). Сборка
`./buildovl.sh starfa.pas STAT starfa.bin` (`make starfa.bin` извлекает
оригинал). Код, пул, глобалы, таблицы и модули совпадают слово в
слово, кроме того же слова 0776. Библиотека отличается версией: в
оригинале PASEOF/READ* на 5 слов короче. ПЕРЕКОД заменяет нынешний
PASISOCD, который добавил бы таблицы ISOP* (0115 слов), которых в
оригинале нет. Подробности — в шапке `starfa.pas`. `snip15.sh` показывает,
во что компилятор 15.0 переводит кусок текста.

Дизассемблированы: КОКА (проверка каталога областей), СВОДКА (карта зон архивного
тома), МДУПЛА (уплотнение архивного тома), ПРОРВА (реорганизация архива
через рабочий том) и АРФА (диалоговая работа с архивом). Их тексты на
BEMSH — `koka.be`, `svodka.be`, `mdupla.be`, `prorva.be` и `arfa.be`. Черновик МДУПЛЫ получен командой
`../tools/disbesm6 -s -a0 -e1 -n mdupla.sym mdupla.bin`, из него убрана
директива `Е` (константы E48…E1 определены в тексте). Дальше
комментарии вписаны прямо в `mdupla.be`; он и есть исходный текст.
ПРОРВА — так же, командой `../tools/disbesm6 -s -a0 -e2 -n prorva.sym
prorva.bin` (`make prorva.bin` извлекает зону 2248/0116). АРФА — командой
`../tools/disbesm6 -s -a0 -e2 -n arfa.sym arfa.bin` и `../py/relabel.py`.
Скрипт заменяет метки внутри диапазонов `.sym` на `имя+смещение`. После
этого шага исходным текстом служит сам `arfa.be`: в нём поправлены числа,
которые дизассемблер принял за адреса, переписаны в читаемом виде таблицы
директив и ключей и вписаны комментарии.

## Сборка и проверка

```sh
make -C arfa koka svodka mdupla prorva arfa
```

* «Золото» — оригинал. `textdump.sh ТОМ ЗОНА С ПО` загружает зону в задаче под dispak,
  снимает дамп барабана и вырезает строки с кодом. КОКА лежит на 2113/1727,
  СВОДКА — на 2113/1702, МДУПЛА — на 2113/1726, ПРОРВА — на 2248/0116,
  АРФА — на 2113/1707, все по одной зоне.
* «Серебро» — пересборка. `zongp.pl -v ФАЙЛ.be 1` транслирует текст BEMSH
  и записывает зону ГП (`ЗОНГП`) с адреса 1. Дамп барабана сравнивается с
  «золотом» командой `diff -q`.

Совпадение «серебра» с «золотом» означает побайтовое совпадение кода.
Пересборка в октябре 2026 г.: 0 ошибок трансляции, оба сравнения прошли.
ПРОРВА и АРФА (ноябрь 2026 г.) тоже совпадают побайтно.

Запуск:

* `koka.b6` — с 2113 на томе 44, проверяет архивный том на приводе 44
  (2248);
* `svodka.b6` — с 2113 на томе 65, номер тома (2048) берётся из ячейки 2000;
* `arfa.b6` — с 2113 на томе 50, с терминала (`ТЕЛ`); под dispak строки
  ввода берутся со стандартного ввода.

Числа ниже восьмеричные, кроме оговорённых. Разряды нумеруются справа от 1.

## Каталоги архивного тома

Сведения взяты из кода КОКИ и СВОДКИ, из таблицы `ЭКВ` модуля КОМАР
(`~/git/re-dispak/komar.be`) и из содержимого тома 2248.

### Зоны каталогов

Каталоги занимают начальные зоны тома, у каждого есть копия «(2)»:

| Зона | Копия | Ключ | Каталог (по СВОДКЕ) | Имя в КОМАРе |
|---|---|---|---|---|
| 0 | 10 | 125240 | ключей (служебная зона) | `ЧТСЛУЖ`, `КЛКЛЮЧ` |
| 1 | 11 | 125241 | областей (главный каталог) | `ЧТГК`, `КЛГК` |
| 2 | 12 | 125242 | приписки | `ЧТКПР`, `КЛКПР` |
| 3 | 13 | 125243 | бюджетов | `ЧТКБЮД`, `КЛКБЮД` |
| 4, 5 | 14, 15 | 125244 | вторичных томов | `ЧТТВТ` |
| 6 | 16 | 125245 | томов (КБОБ) | `ЧТКБОБ`, `КЛКБОБ` |
| 7 | 57 | 125246 | зон (ККУС, каталог кусков) | `ЧТККУС`, `ЧТККУ2`, `ПАРАКК` |
| — | — | 125247 | работ | `КЛКОБ` |

Младшие 3 разряда ключа — вид каталога. Его название СВОДКА берёт по этому
номеру. Каталог, разросшийся за одну зону, продолжается в других зонах тома:
на 2048 у каталога областей есть зоны 3161 и 3162 (копия).

**ККУС (зона 7)** — список кусков всех каталогов. Слова начиная с 3, по
одному на кусок, до нулевого слова:

| Разряды | Содержимое |
|---|---|
| 48–33 | зона куска |
| 32–17 | зона его копии |
| 16–1 | ключ, то есть вид каталога |

Пример с 2248: `0147040634525241` — кусок каталога областей в зоне 3161,
копия в зоне 3162.

**Заголовок зоны каталога** — первые 30 слов:

| Слово | Разряды | Содержимое |
|---|---|---|
| 0 | 48–33 | следующая зона того же каталога (0 — последняя) |
| 0 | 16–1 | ключ |
| 1 | | смысл не установлен (10 и 13 на 2248) |
| 2 | 48–33 | следующая зона в цепочке зон со свободными квантами |
| 2 | 25–1 | шкала свободных квантов: разряд 25−q равен 1, если квант q свободен |

Голова цепочки зон со свободными квантами — разряды 48–33 слова 3 зоны 0
(на 2248 это зона 3161).

### Каталог областей: дерево квантов

За заголовком в зоне идут 31 квант (25 десятичных) по 50 слов: 30 + 31·50 = 2000.

Ссылка на квант — 24-разрядное полуслово:

| Разряды | Содержимое |
|---|---|
| 24–9 | номер зоны |
| 5–1 | номер кванта (0–30) |

Например, `00000404` — квант 4 зоны 1.

Квант содержит три элемента по 15 слов (`LСВЯЗ`) в словах 0, 15 и 32 и
слово связей 47 (`СВЯЗИ`). Поля элемента (смещения из КОМАРа):

| Слово | Содержимое |
|---|---|
| 0 | первые 6 символов простого имени |
| 1 | символы 7–9 имени (левое полуслово) и ссылка вниз (правое): квант со следующим уровнем имён |
| 2 (`ХОЗ`) | шифр хозяина |
| 3 (`ПАРДЛ`) | длина области в зонах (разряды 16–1) |
| 4 (`ПРИПОЛ`) | первая зона области или, при разряде 32, ссылка на приписку в каталоге приписки |
| 5 (`БОББЮД`) | номер тома, на котором лежит область (разряды 12–1) |
| 6 (`ШИФПОЛ`), 11 (`СЛСЛОВ`), 12 (`ДАТЫ`), 13 (`ПОСЗОН`) | по названиям в КОМАРе — шифр пользователя, служебные слова, даты, последняя зона. СВОДКА и КОКА их не читают |

Слово 47 кванта:

| Полуслово | Содержимое |
|---|---|
| левое | ссылка вверх, на отца |
| правое | ссылка на продолжение — следующий квант того же уровня |

На 2248 квант 4 зоны 1 указывает на отца `00000400`, а у кванта 0 ссылка
вниз — `00000404`.

Полное имя области (`ИМЯ.ИМЯ…/шифр`) СВОДКА собирает подъёмом по ссылкам
отцов.

Корень дерева — хэш-таблица в зоне 0, слова 1000–1776: 777 слов по два
полуслова-ссылки. Номер ячейки — свёртка имени (слово 0 элемента) и шифра
хозяина (слово 2).

### Том: КБОБ и карта зон

КБОБ (зона 6, следующие зоны — по слову 0 заголовка) содержит по слову на
том: номер тома в разрядах 48–37 и ссылку на зону со сведениями о томе. В
зоне сведений:

| Слово | Содержимое |
|---|---|
| 0 (`ИНФТОМ`) | резерв для каталогов (разряды 25–16), группа (32–31), вид (30–29): диск, вторичный, лента |
| 1 (`СВОТОМ`) | число свободных зон по учёту |
| со 2 (`КАРТА`) | битовая карта зон, по 48 разрядов на слово, от 48-го разряда к 1-му; 0 — зона свободна |

Область из нескольких кусков описана в каталоге приписки: начиная со
ссылки из слова 4 идёт список полуслов-кусков, «начальная зона, длина».

## Что проверяет КОКА

КОКА проверяет целостность дерева каталога областей на томе 44. Она
читает зону 0 (корневая хэш-таблица и голова цепочки свободных) и зону 7
(ККУС), отбирает из ККУС куски вида 1 — зоны каталога областей. Для каждого
кванта этих зон она заводит слово учёта: кто на него ссылается и откуда,
пуст ли он, просмотрен ли.

Порядок работы:

1. **Ссылки из корня.** Каждое ненулевое полуслово хэш-таблицы зоны 0
   помечает квант как корневой, с номером ячейки.
2. **Цепочка свободных.** КОКА проходит цепочку зон со свободными квантами.
   Пустая шкала у зоны в цепочке — ошибка `НЕТ СВОБ.`. Каждый квант из шкалы
   помечается как свободный.
3. **Обход дерева.** Повторяется, пока появляются новые пометки. Каждый
   помеченный и ещё не просмотренный квант проверяется:
   * свободный квант должен быть пуст — иначе `СВОБ.КВАНТ НЕ ПУСТ`. Пустым
     считается квант с нулевыми словами 0, 15, 32 и 47;
   * у корневого кванта каждый элемент должен лежать в ячейке хэш-таблицы,
     вычисленной по его имени и хозяину, — иначе `ПЛОХОЙ КЛЮЧ`;
   * у остальных квантов отец в слове 47 должен совпадать с квантом, который
     на самом деле на него ссылается, — иначе `ССЫЛКА ВВЕРХ`;
   * ссылки вниз из слова 1 трёх элементов и ссылка на продолжение из слова
     47 помечают свои кванты.
4. **Проверка каждой пометки.** Ссылка должна вести в зону каталога
   областей — иначе `НЕСУЩ.ЗОНА … НЕТ ЗОНЫ !`. На квант не должны ссылаться
   дважды — иначе `ДВАЖДЫ ЗАНЯТ` с обоими источниками (`ОТЕЦ:`, `ИЗ:`).
5. **Потерянные кванты.** Квант, до которого не дошёл обход, потерян:
   `ПОТЕРЯН !` — если пуст, `ПЛОХО:ПОТЕРЯН !` — если в нём что-то есть.

Если ошибок нет, КОКА печатает `ОШИБКИ В КАТАЛОГЕ НЕ ОБНАРУЖЕНЫ!` (так на
2248). При ошибках после сообщений идёт таблица всех квантов, по шесть строк
в группе. Её столбцы: `КВАНТ`, `ФАКТ.ОТЕЦ` / `ССЫЛАЮТСЯ ИЗ` (по слову учёта),
`ОТЕЦ ИЗ СВЯЗИ` / `ПРОД.ИЗ СВЯЗИ` (по слову 47), `НИЖНИЕ УРОВНИ` (слово 1
трёх элементов).

КОКА только читает: каталоги приписки, бюджетов, томов и карту зон она не
проверяет. Это делает СВОДКА.

## Что делает СВОДКА

Номер тома (запись 2–10, то есть цифрами) берётся из ячейки 2000 или из
шифра задачи, пароль — из ячейки 2001. При терминале пароль администратора
запрашивается (`КЛЮЧ АДМ.:`).

Корневой том берётся одним из двух способов:

* с привода 40, если он заказан;
* через экстракод Э63 с ключом `КЛЮЧАР`. Нужны права администратора, иначе
  `НЕ ИМЕЕТЕ ПРАВА`.

Все занятые и свободные отрезки зон тома СВОДКА собирает из трёх источников:

* **Области.** Все элементы каталога областей, лежащие на этом томе, с
  полными именами. Для области из нескольких кусков разбирается приписка;
  возможны ошибки `НЕТ ПРИПИСКИ В ЗОНЕ` и `ПРИПИСКА НЕ ОКОНЧЕНА`. Если у
  какой-нибудь области 10 кусков и больше — `ТРЕБУЕТСЯ РЕОРГАНИЗАЦИЯ ТОМА!`.
* **Куски каталогов.** Берутся из ККУС тома, с номером куска и пометкой
  копии «( 2 )».
* **Свободные отрезки.** Берутся из карты зон тома в КБОБ (`НЕТ ТОМА В КБОБ`,
  `НЕТ ИНФОРМАЦИИ О ТОМЕ`). Свободное по карте печатается как `ФАКТИЧЕСКИ
  СВОБОДНО`, рядом — счётчик `СВОБОДНО` из КБОБ.

Отрезки сортируются по начальной зоне и печатаются таблицей «число зон,
начало–конец, номер куска, владелец». Затем идёт проверка стыков:
перекрытие печатается в списке `ДВАЖДЫ ЗАНЯТЫ:`, дыра — в списке
`ПОТЕРЯНЫ:`. Оба списка дают только первую зону каждого случая.

По тому 2048 (запуск `svodka.b6` в октябре 2026 г.):

* свободно 41366 зон по учёту и по карте;
* каталоги лежат в зонах 0–16, 57, 3161 и 3162;
* области — от АКТИВАТОРа (47) до ДОКЭБ (3220–3777);
* `ПОТЕРЯНЫ: 17` — зоны 17–46 не заняты ни каталогом, ни областью и не
  отмечены свободными.

## Что делает МДУПЛА

МДУПЛА уплотняет архивный том: сдвигает области вниз, закрывая дыры, и
правит каталоги. Параметры — с ячейки 4000:

| Ячейка | Содержимое |
|---|---|
| 4000 | уплотняемый том, текстом (`Б002048`) |
| 4001 | буферный том, текстом; он не должен входить в архив |
| 4002 | корень архива (разряды 48–33) и том копий каталогов (32–17), цифрами 2–10; 0 — взять у системы |
| 4003 | первая зона уплотнения для обычного тома |

Приводы: корень — 40, копии — 50, уплотняемый — 60, буфер — 67.

Порядок работы:

1. Уплотняемый том ищется в КБОБ корня (`МДУПЛ НЕТ В АРХИВЕ`), буферный — тоже
   (`БУФЕРНЫЙ ДИСК ПРИНАДЛЕЖИТ АРХИВУ`).
2. Если уплотняется сам корень, сначала переносятся каталоги — с зоны 17
   (или 20, если копии на другом томе). Соответствие старых и новых зон
   запоминается, затем все ссылки в каталогах переписываются.
3. Обход каталога областей. Зоны каждой области на этом томе копируются в
   буфер подряд, с новой границы; в элементе меняется начальная зона. Зона 57
   (копия ККУС) не переносится. Область, которая через неё не проходит,
   делится на два куска приписки.
4. Карта зон тома в КБОБ перестраивается (разобрано не полностью).
5. Зоны переписываются из буфера обратно на уплотняемый том.

Сообщения: `УПЛОТНЕНИЕ АРХИВНОГО ДИСКА ЗАКОНЧИЛОСЬ`, `РАБОТА ЗАКОНЧЕНА
НОРМАЛЬНО`, `НЕВЕРНЫЙ НОМЕР ТОМА`, `ОШИБКА В КАТАЛОГЕ ДУБЛЬ-ЗОН`,
`ОШИБКА В ЗОНЕ ПРИПИСКИ`, `ОШИБКА В КАТАЛОГЕ БОБИН` и просьбы
`УСТАНОВИ …` для четырёх томов.

**Ошибка в `isarch`.** Перебор КБОБ начинается с адреса из левого
полуслова слова 1 зоны КБОБ. ОС (ГИДРА, НЕРЕЗА) и СВОДКА всегда начинают
со слова 2. На архиве 2248 это полуслово 0, поэтому поиск начинается с
заголовка, уходит по случайным шагам и не кончается: МДУПЛА зацикливается
на 01162–01170 при любых параметрах.

С заменой одной команды (слово 01157: `слиа 74000(М1)` на
`слиа 74002(М1)`) МДУПЛА работает. Проверено на копиях: образ 2248 подан
как том 2048, параметры — `Б002048`, `Б002052`, `C 1004 4040 2200 0000`.
После уплотнения:

* КОКА: `ОШИБКИ В КАТАЛОГЕ НЕ ОБНАРУЖЕНЫ!`;
* СВОДКА: каталог областей переехал из 3161/3162 в 17/20, области сдвинуты
  вниз, СЛУГА разбита на два куска (вокруг зоны 57);
* содержимое всех 31 области совпадает с исходным;
* свободных зон по-прежнему 41366, потерянные 30 зон (17–46 до
  уплотнения) оказались в конце, 3750–3777.

## Что делает ПРОРВА

ПРОРВА переносит области архива на рабочий том, переписывает его на место
уплотняемого и обновляет каталоги. Контрольные точки позволяют продолжить
прерванную работу. Колода `prorva.b6`: `ЕВ1` с `Э70` по слову 2 читает зону
2248/0116 в адреса 0–1777, работа продолжается с ячейки 2. Слово 1 содержит
имя программы, и на его место пишется вид работы — текст в ячейке 2000:
`УПЛТОМ` (уплотнить том) или `ВКЛТОМ` (включить том в архив). Параметры
задаются текстом с 4001 в виде `ИМЯ/НОМЕР,…`. С тома на приводе 44 переносятся
только перечисленные в них области.

Приводы: 31 — корень архива (каталоги читаются), 32 — рабочая копия каталогов,
33 — том для итоговых каталогов, 37 — рабочий том (МДРАБ), 40 — уплотняемый
(МДУПЛ), 40–44 — тома архива.

Этапы:

0. Все куски каталогов из ККУС корня переписываются в рабочую копию (32). Из
   зон КБОБ берутся карты томов 37, 40–44. При `ВКЛТОМ` запись тома 37
   добавляется в КБОБ. При `УПЛТОМ` том 37 занимает место тома 40, и их
   объёмы должны совпадать. Затем обходятся зоны каталога областей. Каждая
   область, лежащая на томе 40–44, получает место на томе 37: зоны снимаются
   с карты своего тома, на 37 отводятся подряд, элемент (слова 2, 4, 5) и
   приписка исправляются. Соответствие новых и старых зон хранится в
   таблице 10000. Карты пишутся обратно в КБОБ, зоны областей
   переписываются на 37.
1. Только для `УПЛТОМ`. Том 37 переписывается на 40 зона в зону, свободные
   зоны заполняются кодом `5252…`.
2. Если на приводе 33 есть том, каталоги переписываются из рабочей копии
   на 33. Иначе выдаётся `РЕОРГАНИЗАЦИЯ ЗАКОНЧЕНА БЕЗ ЗАПИСИ КАТАЛОГОВ НА МД 33.`

Перед этапами 1 и 2 текст `ЭТАП n` и карта тома 37 (4401–4577)
записываются в слова 401–577 служебной зоны рабочей копии. Это КТЧ:
`ФИКСАЦИЯ КТЧ НА ЭТАП n ВЫПОЛНЕНА`. Если при запуске КТЧ найдена,
выдаётся `РЕСТАРТ:КТЧ ЭТАП n`, и работа продолжается с этапа n. Реакция на
авост ставится через `Э50 '103'`. При коде 052 (по-видимому, сбой МД)
выдаётся `ОШ.МД ПРИ …` с названием этапа, при прочих кодах —
`НЕОБРАБАТЫВАЕМЫЙ АВОСТ!`. Номер тома на приводе ПРОРВА, по-видимому,
получает через `Э50 '105'`, тип МД — через `Э50 '156'`.

Странности оригинала:

* в проверке карт томов 40–44 (`chkmap`) `по` ведёт на текст `НЕ НАШЕЛ
  КАРТУ ТОМА` (01027), а не на код `enomap` (01023), который печатает этот
  текст с номером тома. Ссылок на `enomap` нет. Текст выполнится как
  команда `выпр`, привилегированная, и задача, видимо, прервётся;
* в сообщении `ВТОРАЯ КАРТА` вместо номера тома печатается слово
  `sizes+1(М1)`;
* текст `НЕТ МЕСТА В КАТАЛОГЕ ТОМОВ` (0755) нигде не используется.

**Прогон на копиях (ноябрь 2026 г.).** Колода `prorva.b6` запускалась
на копиях 2248 и 2345, а также с образом 2248, поданным как том 2048 (в
КБОБ образа одна запись — том 2048). В обоих случаях печатается шапка
протокола, `Э50 '105'` находит том только на приводе 44, и на этапе 0
задача кончается `ЗАПРЕЩ.КОМАНДА` на 01027: это переход `по` на текст в
`chkmap` (см. выше), то есть карта тома не найдена.

Причина — формат записи тома. Запись в зоне КБОБ ищется по маске
`volmsk` (`7777000000001777`): номер тома (разряды 48–37) и длина записи
(разряды 10–1) должны совпасть с паспортом из `vols`. Длину ПРОРВА берёт
из таблицы `typcod` по коду типа МД от `Э50 '156'`: 027 (2 + 21 слово
карты, 996 зон, `typsiz`) или 0126 (2 + 84 слова, 3996 зон). В образе
запись тома 2048 — `4000002000000622`: длина 0622, карта на 400 слов, то
есть до 19200 зон (свободных 41366). Такой длины ПРОРВА не знает, и
запись не опознаётся. Программа рассчитана на архив на МД с картой до 3996
зон; на этом образе без правки таблицы типов она не работает. Числа
зон 996, 3996 и 19200 и слов карты 21, 84, 400 — десятичные.

## Что делает АРФА

АРФА (`*** А R F А *** ВЕРСИЯ ОТ 14.12.88`) — диалоговая оболочка
архива. Она читает с терминала строку-директиву, разбирает её в блок
запроса и обращается к архиву экстракодом `Э63`. В A при этом `КЛЮЧАР`,
в РМР — параметр, адрес указывает на блок запроса, код ответа
возвращается в М16. Затем АРФА печатает ответ. Это соглашение
подтверждается `dnepr.be:1002` (`ИС63`, `ИСУНОУ`, `ИСДОЗ`) и СВОДКОЙ.

Строение зоны:

| Адреса | Содержимое |
|---|---|
| 2–3 | переход на начало; `type` — печать текста на терминал |
| 4–43 | таблица директив `cmdtab` |
| 45–67 | таблица ключей `keytab`: `пб` на разбор значения и буква ключа |
| 71–150 | константы E48…E1 |
| 151–412 | рабочие ячейки, блок запроса `rq`, ответ `ans`, строки ответов, шапка |
| 413–1037 | разбор строки: символы, числа, ключи |
| 1040–1451 | выполнение директив и печать ответов |
| 1540–1775 | модуль терминала (`Э71`, `Э64`) со своими константами |

Зона 2113/1723 похожа на образ той же программы: в ней есть таблица
директив и те же тексты, но со сдвигом и с искажёнными символами. Формат
не установлен, зона не разбиралась.

### Директивы

Строка: `КОМ[...] [имя][:] ключ=значение,ключ=значение,...`. Значимы
первые три буквы директивы, остальные пропускаются. Ключ — первая
буква слова; после неё до `=` или `:` могут идти любые буквы. `*` среди
параметров ставит признак `star`: для СВЕ он значит «печатать все слова
ответа». `КОН` кончает работу.

Номер директивы в таблице (№, десятичный, 1–32) записывается в разряды
48–43 слова 0 блока; начиная с 27-й к нему прибавляется 026. Коды сверены с СВОДКОЙ:
`rights` (`м40п'Ш'`, код 016) — это АДМ, `rdarz7` (код 065) — ХХХ. dispak
(`extra.c`, `arfa()`) знает тоже только эти два кода: 016 — подтверждение
пароля администратора, 065 — чтение зоны архивного тома.

разряда 48 слова 1, по 8 разрядов на символ, с концом 0377; в слове 0
при этом ставится E4. Директива без ответа печатает только сообщение
по коду ответа: `Э50 '202'` даёт текст причины авоста или диагностики
архива, коду 0 соответствует `ВЫПОЛНЕНО`.

### Ключи

Значение пишется либо в слово 0 блока (rq), либо в параметр в РМР
(yparm):

| Ключ | Значение | Куда |
|---|---|---|
| N | восьмеричное, 6 разрядов | rq 42–37 (у ОСВ — rq 6–1) |
| Ш | шифр, 6 цифр | yparm 48–25 |
| П | восьмеричное, 12 разрядов | rq 36–25 |
| L | восьмеричное | yparm 16–1; у РЕС — rq 24–1, у ВНБ — rq 40–25; у СДВ и ДЛИ со знаком: `-` — E21, без знака у ДЛИ — E22, `L=П` у ДЛИ — E22 и E21, число — rq 20–5 |
| Д | `З` — 0, `Ч` — E12 | rq |
| К | ровно 6 символов (ключ, пароль) | слово 1 блока |
| А | шифр, 6 цифр | у КТЛ — yparm, у прочих — rq 24–1 |
| Н | восьмеричное, 12 разрядов | rq 24–13 |
| Т | восьмеричное, 5 разрядов | yparm 22–18 |
| Р | права: `Н` — 0, `Ч` — 1, `З` или `М` — 2 | yparm 2–1 |
| М | `Д`/`Н` | rq E24 |
| Б | до 4 десятичных цифр | у НОВ — тетрадами в rq, у прочих — двоично в rq 24–13 |
| У | `Д`/`Н` | rq E23 при `Н` |
| Г | цифры 0–3 (группы) | rq 40–37; у ВНБ — ровно одна, номер в rq 21–20 |
| В | `Д` — 1, `Н` — 2, `Л` — 3 | rq 26–25, у ВНБ — rq 19–18 |
| И | `Д`/`Н` | yparm E17 |
| С | восьмеричное n | yparm E(0110−n), то есть n от 030 до 0107; меньшие n не проверяются |
| Ч, З | — | всегда `ОШИБКА !` |

Смысл полей для архива здесь не устанавливался. Его нужно сверять с
разбором блока в модуле РА (`ra.be`, таблица `КОНКАТ`).

Ошибки разбора — `НЕТ ДИРЕК`, `<ключ> - ОШИБКА !` (ключ не разрешён или
нарушен синтаксис) и `ОШИБКА В ПАРАМ. <ключ>` (плохое значение). После
них снова выдаётся приглашение.

Ответы печатают подпрограммы `rtab`. Номер подпрограммы — число директив
с ответом, стоящих в таблице раньше:

* КТО — `ХОЗЯИН` и шифр, затем права по шифрам из ответа и `ПРОЧИЕ` (`НЕТ`, `ЧТ`, `ЧТ/ЗП`);
* СВЕ — `СОЗДАЛ`, `ДЛИНА`, `ГРУППА`, `ИНД.`; со `*` — ещё слова ответа 0–015 построчно;
* КТЛ, КАТ — каталог порциями по 040 элементов до слова −1. Без имени, но с шифром
  для каждой области делается второй запрос, и печатается его ответ;
* ИМЯ — ответ как текст; ЗСД — `СДВИГ` со знаком; АДМ и ШИФ — два поля ответа;
* ЗБЮ — номер, `ГРУППЫ`, строки `РЕЗ-Д:`, `Н/Р  :`, `РЕЗ-Л:`, затем порциями по 0100
  слов шифры с их группами.

### Терминал

Модуль терминала выводит текст через `Э71`. Номер терминала он узнаёт
при первом выводе (`Э71` по слову −1). Копия идёт в протокол задачи
через `Э64`. Через каждые `pglen` строк (по умолчанию 016) модуль
спрашивает `ИДТИ?`; непустой ответ прерывает печать ответа. Строки,
которые начинаются с команды терминала, разбираются в самом модуле:

| Команда | Действие |
|---|---|
| `ШАГnn` | строк на страницу, две восьмеричные цифры |
| `ЭХО`, `ЭКР`, `ПЕЧ` | переключить эхо, вывод на экран, копию в протокол (`<КОМ> УСТ.` / `ОТМ.`); экран и копия не выключаются оба; `ПЕЧ` сначала выполняет `Э62 '76'` — отказ от режима «Инкогнито» |
| `АЦП` | разгрузка выходного потока печати (`Э62 '42'`) |
| `СБР` | приказ ПРО (`Э50 '1212'`, как ТПРО в `starfa.pre`) |
| `КНЦ` | конец задачи (`Э74`) |
| `///` | секретный приём, без эха (разряд E38 в слове обмена); эха и копии в протокол нет |

Первое прерывание с терминала печатает `НЕ СПАТЬ!`, второе подряд кончает
задачу.

**Прогон под dispak (ноябрь 2026 г.).** `arfa.b6` на копии 2113 печатает
шапку и приглашение `=`. Код 016 (АДМ) dispak только принимает, ответа не
формирует. Поэтому `АДМ Ш=123456,К=АБВГДЕ` печатает `419900  АДМ.123456`:
это содержимое A после экстракода, а не ответ архива. Остальные коды
dispak передаёт экстракодам супервизора (`cu.c`, `E_UNIMP`). Там КТО без
имени даёт `ТАКОГО ИМЕНИ НЕТ`, НОВ — `ВЫПОЛНЕНО` (по-видимому, без
действия), КТО с именем — `ЗАПРЕЩ.НАПР.В ЭК` на 01065. Архива dispak не
моделирует.
