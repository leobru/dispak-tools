## Identification evidence

The old matcher discarded every operand and accepted 90% of opcode words. It could mistake P/2 for P/3 and zero-filled commons for executable routines. The current matcher preserves numeric operands, checks internal relocation, keeps ENTRY aliases with their modules, and reports ambiguous locations.

Whole-module matches and shorter entry-fragment matches are recorded separately in `analysis.json`. A fragment identifies an entry candidate; it does not establish the boundary or dependencies of its original object module. Names found by different references at conflicting addresses are omitted from `.sym` files.

Symbol files use C for code and D for data. The adjacent disassemblies retain all extracted words. Unnamed words and out-of-extract calls require recovery before further runtime profiles can be declared linkable. The reviewed profiles override candidate names only for their own byte-identical source images.
