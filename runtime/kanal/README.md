# Что такое КАНАЛ.КОД

`КАНАЛ` — интерактивная служебная программа для работы с аппаратным
мультиплексным каналом: просмотр его регистров, выдача слов, контроль обмена,
пересылка файлов библиотеки Монитора и выполнение дисковых запросов через
подключённое устройство. Она написана на Паскале с машинными вставками Э76.
Это предварительный разбор назначения и интерфейса перед декомпиляцией.

Программа сама представляется строкой КОИ-8 по адресу `04263`:

```text
 ПРОВЕРИМ КАНАЛ! (88/10/21)
```

Адреса и машинные коды ниже восьмеричные. Размеры в словах — десятичные.

## Какой образ исследован

| Поле | Значение |
|---|---|
| Каталог тома 4001 | `КАНАЛ`, зоны `0023–0027`, пять зон |
| Извлечённый файл | `runtime/images/4001/0023-kanal.bin`, 5120 слов |
| Вход программы | `02012`, старт `04053` |
| Паскалевский код | `02012–04057` |
| Константы | `04060–04316` |
| P/1D, начало runtime | `04317`, `04513` |
| FREE | `07250` |
| Число страниц P/BOOT | `3` |

При штатном запуске читаются только зоны `0023–0025`. Зоны `0026–0027`
выделены каталожной записи, но P/BOOT их не читает. Их содержимое не следует
включать в исходник этого запускаемого образа.

## Низкоуровневый доступ

Перед Э76 программа устанавливает РЖ `043` и загружает номер канала в М15.
Режим с признаком `040` согласуется с обработчиком `ЭКМУЛЬ` в сохранившихся
исходниках ОС СВС/ДИСПАК (`re-dispsvs/src/khlam.bemsh`, метки `ЭКМУЛЬ`,
`ПАРОЛЬ`, `ЭКИ`, `ОБРКАН`). Этот обработчик прямо назван «экстракод обращения
к программным мультиплексным каналам» и проверяет этот признак РЖ.

Соответствующие процедуры в КАНАЛ:

| Адрес | Операция | Машинная вставка |
|---|---|---|
| `02341` | Захват/проверка доступности канала | Э76 `0`; успех при нулевом результате |
| `02353` | Прочитать входной регистр | Э76 `2`, маска `777777` |
| `02363` | Прочитать выходной регистр | Э76 `3`, маска `777777` |
| `02373` | Записать выходной регистр | A AND `777777`; Э76 `1` |
| `02424` | Показать входной регистр | Заголовки разрядов `18 … 1`, затем 0/1 |
| `02452` | Показать выходной регистр | Такие же заголовки и 18 значений 0/1 |

Процедура `02402` выдаёт одно слово протокола:

| Разряды, с единицы | Назначение | Маска |
|---|---|---|
| 1–16 | Данные | `177777` |
| 17 | Дополнение до нечётного числа единиц | `200000` |
| 18 | Синхронизация обмена | `400000` |

Она считает единицы в 16 битах данных, добавляет бит нечётности, сохраняет
состояние синхронизации в выходном слове и затем меняет этот бит. Приёмник
`02627` опрашивает входной регистр, сравнивает бит синхронизации, проверяет
нечётность и выделяет 16 бит данных. Сообщения `ЧЕТНОСТЬ СЛОГА:` и
`TEST FAILED. OUT: … IN: …` находятся соответственно по `04165` и `04171`.

Это определяет аппаратную сторону интерфейса. Конкретная модель устройства
или машины на противоположном конце из этого образа пока не установлена.

## Команды

Основной цикл начинается с `03705`, приглашение — `. `. Слова команд
хранятся в `04301–04316`; сравнение допускает сокращения.

| Команда | Действие | Основная процедура |
|---|---|---|
| Пустая строка | Показать входной регистр | `02424` |
| `.` | Показать выходной регистр | `02452` |
| `КНЦ` | Закончить программу | Ветка `03725–03732` |
| `БИБ` | Показать текущую библиотеку или выбрать другую | Ветка `03733–03751` |
| `ВЫД` | Выдать число в канал с оформлением слова протокола | `02402` |
| `ФАЙЛ` | Спросить `КУДА?`; выбрать направление пересылки | Ветка `03761–04007` |
| `ТУДА` после `ФАЙЛ` | Читать локальный файл через OPENF/Э70 и посылать в канал | `03245` |
| `СЮДА` после `ФАЙЛ` | Принимать данные из канала, создавать и записывать локальный файл | `03070` |
| `КАНАЛ` | Выбрать номер канала | `03401` |
| `ЧТ` | Выполнить дисковое чтение по протоколу канала | `03504`, параметр операции `2` |
| `ЗП` | Выполнить дисковую запись по протоколу канала | `03504`, параметр операции `1` |
| `ДИСК` | Задать параметры диска и выполнить инициализацию | `03432` |

Аргументы `ВЫД` и `КАНАЛ` читаются по основанию 8. Номер канала проверяется
на диапазон `0–77`; вне диапазона печатается `ILLEGAL CHANNEL NUMBER.`.
Точная грамматика остальных аргументов ещё не восстановлена целиком.

## Зачем здесь файловая и дисковая части

Локальные файлы открываются через библиотечные LIB, MKNAME, MAKEF, OPENF и
CLOSEF; в двух направлениях используются метки `WRFILE` и `RDFILE`.
В вызовах MKNAME передаётся расширение `КОД`. Буфер локального дискового
обмена размещён с `74000`; чтение и запись страниц выполняются через Э70.
Окончание файлового потока отмечается словом из всех единиц.

Другая часть работает через канал. Процедуры `03432` и `03504` формируют
управляющее слово и поля адреса/длины, передают их через `02655` и проверяют
возвращённый статус. Есть отдельные сообщения:

```text
INITIALIZATION FAILED:
NO DISK SPECIFIED.
ОТРИЦАТЕЛЬНАЯ ДЛИНА - НА МНИМЫЙ ДИСК
DISK ERROR:
```

Таким образом, это также средство обслуживания подключённой системы,
умеющее передавать код и обращаться к её диску. Точная раскладка всех полей
этого протокола и смысл «мнимого диска» требуют дальнейшего разбора; считать
их стандартными полями Э70 было бы преждевременно.

## Инициализация и границы установленного

`03372` получает младшие три бита результата Э50 `114`. В `03622` код `0`
выбирает начальный канал `77`, код `1` — канал `1`; остальные значения дают
`UNKNOWN CPU!`. Названия этих двух вариантов CPU в бинарнике не найдены.
После заставки выполняется захват канала. При неуспехе печатается
`НЕ ПРОВЕРИМ - ЗАНЯТ.` и происходит возврат по адресу `00002`.

Низкоуровневый обмен сосредоточен в перечисленных вставках Э76. Перед восстановлением
Паскаля уже можно дать осмысленные имена процедурам и отделить этот обмен
от файловой библиотеки. Для проверки реального обмена понадобится понять
вторую сторону канала либо воспроизвести её протокол. В этой работе образ
не запускался: выводы основаны на коде, константах и исходнике обработчика
экстракода.

[kanal.sym](kanal.sym) добавляет имена установленных процедур к исходной
карте runtime. Эти имена восстановлены по назначению, а не извлечены из PMD.
