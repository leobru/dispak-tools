# Разбор PRINT.КОД

PRINT — построчная печать текстовых файлов библиотеки Монитора на АЦПУ,
включая перебор файлов по маске через FIRSTF/NEXTF.
Программа переводит буквы в печатный репертуар ГОСТ, выделяет прописные
повторными ударами и умеет принимать текст в альтернативной кодировке PC.
В отличие от FPRINT, здесь нет раскладки двух страниц на одном листе.

Разбор основан на машинном коде и константах. Образ в этой работе не запускался;
Паскаль и побитовое воспроизведение ещё не восстановлены. Имена процедур в
[print.sym](print.sym) даны по их назначению, исходные имена неизвестны.
Адреса и коды символов ниже восьмеричные; размеры и параметры — десятичные.

## Образ

| Поле | Значение |
|---|---|
| Каталог 4001 | `РRINТ`, зоны `0051–0056`, шесть зон |
| Извлечённый файл | `runtime/images/4001/0051-print.bin` |
| Вход | `02012`, старт `02710` |
| Паскалевский код | `02012–02714`, 451 слово |
| Константы | `02715–03032` |
| База М1, P/1D | `03033` — устанавливается в `10775` |
| Начало runtime | `04342` |
| Последнее ненулевое слово в загружаемых страницах | `11216` |
| Начальный стек из `02010.R` | `14000` |
| Число страниц в `02011` | `5` |

P/BOOT загружает только зоны `0051–0055`, память `02000–13777`.
Шестая каталожная зона этим загрузчиком не читается. Слова выше `11216`
в пяти загружаемых страницах нулевые; их нельзя принимать за утраченный код.

## Команда

Строка по адресу `02737`, ровно 68 байт:

```text
USAGE: PRINT [-A![-8]] <FILE_NAME> [<PAGE> [<LEFT> [<NAL> [<TABS]]]]
```

Именно `!` и недостающая закрывающая угловая скобка у `TABS` находятся
в образе. Из кода следует такая последовательность аргументов:

```text
PRINT [-<буквы опций>] <файл> [PAGE [LEFT [NAL [TABS]]]]
```

| Аргумент | Начальное значение | Что делает |
|---|---:|---|
| `A` в начальной группе опций | выключено | Перекодирует входные байты `200–377` по таблице `04217` |
| `8` в той же группе | — | Выключает эту перекодировку |
| `S` в той же группе | выключено | Переключает замены `237 → 136`, `276 → 137` после перекодировки |
| `PAGE` | 0 | Ненулевое значение включает предварительное пропускание текста по FF; подробность ниже |
| `LEFT` | 0 | Перед основной строкой выдаётся `LEFT+2` пробела |
| `NAL` | 2 | Число дополнительных проходов по прописным буквам |
| `TABS` | 8 | Шаг табуляции |

Опция `S` отсутствует в справке, но явно распознаётся в `02261–02267`.
Один начальный минус открывает группу; принимаются только символы `8`, `A`,
`S`, без перевода регистра. Например, код допускает `-AS` и `-A8`.
Повторное `S` отменяет предыдущее; для `A/8` действует последнее указание.
Смысл названия `S` не установлен; две замены установлены буквально.

Команда берётся из общей ячейки Монитора `00055`: копируются максимум
80 символов до LF. При пустой строке печатается `FILE NAME FOR PRINTING ?`,
затем вызывается библиотечная процедура ввода текста. Имя ограничено
83 символами с последующим терминатором. Для файловой библиотеки используются
активная библиотека из `00003`, расширение по умолчанию `TXT`, `FIRSTF` для
выбора первого файла и `OPENF` для чтения. После каждого файла `NEXTF` выбирает
следующее совпадение; результат 15 означает конец перебора. Сигнатуры FIRSTF
и NEXTF подтверждаются сохранившимся [исходником COPY](../../runtime/sources/4001/copy.b6).
Ошибки `LIB`/открытия декодируются через `ERROR` в строку 84 символов.

Ненулевой `PAGE` нельзя пока описывать как обычный номер первой страницы:
в `02456–02467` счётчик, первоначально равный нулю, увеличивается на каждом
FF; пропуск заканчивается, когда он **строго больше** `PAGE`, либо при EOF.
То есть `PAGE=1` пропускает текст до второго FF включительно. При `PAGE=0`
предварительный проход целиком обходится. Это свойство кода, а не поправка
к предполагаемому интерфейсу.

## Печать

Вместо буфера листа имеются два массива по 256 слов:

| Адреса | Назначение |
|---|---|
| `03206–03605` | Основная строка, элементы 1–256 |
| `03606–04205` | Строка повторного прохода, элементы 1–256 |
| `04206` | `TABS`, исходно 8 |
| `04207` | `NAL`, исходно 2 |
| `04210` | `LEFT`, исходно 0 |
| `04211–04213` | Трёхсловное имя файла; последнее слово печатается как имя |
| `04214–04216` | Опции A, S и признак наличия повторного прохода |

Процедура `02047` выдаёт отступ, основную строку и перевод строки. При наличии
прописных она затем `NAL` раз выдаёт `+`, вторую строку и перевод строки.
Вторая строка содержит печатный знак в позициях прописных и пробелы в остальных
позициях. Таким образом, по умолчанию прописная получает **три удара**.
Ударение на той же строке задаётся управляющим `+` в первой позиции;
он проходит через библиотеку вывода на АЦПУ. Физический поток печати ещё
не проверен запуском.

Перед выдачей действует необычное ограничение: если длина больше 126,
она заменяется на 124 (`02053–02055`). Переноса остатка на следующую строку
нет. При этом символы уже записываются в массив до обработки LF: защиты
записи от выхода за 256 элементов в основном цикле не видно.

| Входной код | Действие основного цикла |
|---|---|
| EOT `004` | Последовательность Э64, итог `PAGES=… LINES=…`, Э62 `42`, завершающий вызов Э50 `1212`, выход из цикла |
| TAB `011` | Добавить пробелы в оба массива до следующего кратного `TABS` |
| LF `012` | Напечатать строку, обнулить длину и признак повторного прохода, увеличить счётчик строк |
| FF `014` | Последовательность Э64 и увеличение счётчика страниц |
| Другие | Преобразовать и добавить в строку |

FF не вызывает печати накопленной строки и не обнуляет её длину.
EOF завершает чтение без выдачи незаконченной строки и без ветки EOT с итогами.
CR `015`, BS `010` и NUL `000` не имеют собственных веток в приложении;
последующая обработка управляющих байтов зависит также от текстового runtime.
Это отличается от явно заданных действий FPRINT над этими символами.

Перед содержимым `02114` печатает `PRINTING FILE : <имя>.TXT`, затем передаёт
внешней процедуре `05540` три слова заголовка: шесть пробелов, имя и `.TXT  `.
Она разворачивает 18 знаков через растровый шрифт `05577–05734`, строит восемь
строк увеличенного изображения и выдаёт их через АЦПУ. Это крупный титульный
заголовок файла; календарной процедуры здесь нет.

## Кодировки и буквы

Без `-A` текст обрабатывается как КОИ-8. Таблица `04217` при `-A` соответствует
расположению русских букв в CP866: `200–237` — прописные, `240–257` и
`340–357` — строчные; псевдографика заменяется пробелами. Название CP866 —
современное сопоставление таблицы, не строка, найденная в программе.
Особенности таблицы: `Ё/ё → Е/е`, а прописная `Ъ` превращается в код строчной
`ъ` (`337`). Поэтому она не получает повторных ударов.

После опций буквы переводятся в общий печатный регистр. В строке повторного
прохода остаются только ASCII `A–Z` (`101–132`) и КОИ-8 `Ю–Ч` (`340–376`).
КОИ-8 `Ъ` (`377`) исключена. В отличие от FPRINT, PRINT не составляет
строчную `ъ` из мягкого знака и апострофа.

Вывод затем переводится в ГОСТ таблицей TTIO `10130–10167`.
Есть явные замены знаков в приложении; итоговые знаки ГОСТ:

| Вход КОИ-8 | Печатается |
|---|---|
| `?` | `°` |
| `@` | `↑` |
| `\` | `≡` |
| `^` | `¬` |
| обратный апостроф | `’` |
| `{`, `}` | `⩽`, `⩾` |
| `|` | `|` |
| `~` | `‾` |
| `ъ`, `Ъ` | `’` |

Это точное отображение байтов, а не исправление под современную ASCII.
[analyze.py](analyze.py) извлекает таблицу альтернативной кодировки и строит
[analysis.json](analysis.json): для каждого входного байта `040–377` и четырёх
сочетаний A/S указаны промежуточный байт, код ГОСТ и признак повторного прохода.
Это статическая модель перечисленных участков, не результат эмулятора.

## Процедуры и библиотека

| Вход | Восстановленное назначение |
|---|---|
| `02013` | Скопировать командную строку в Паскалевский text |
| `02036` | E64ONE, E64TEXT, E64ZERO — три операции Э64, как в FPRINT |
| `02047` | Напечатать строку и дополнительные проходы |
| `02102` | Пропустить пробелы |
| `02114` | Заголовок файла и вызов крупной печати |
| `02144` | Справка и Э74 |
| `02152` | Инициализация файлов |
| `02171` | Основная программа |
| `05466`, `05540` | Построить и вывести крупный заголовок |
| `06137`, `06170`, `06556` | LIB, OPENF, ERROR |
| `07137` | FIRSTF, внутри вызывает MKNAME `07336` |
| `07301` | NEXTF, получить следующее имя, соответствующее маске |
| `07531` | Подключить файловый дескриптор к text |

В `02705–02707` результат NEXTF сравнивается с целым 15; при несовпадении
выполняется возврат к обработчику статуса `02405`, затем открытие следующего
файла. Это полноценный цикл печати выборки, а не завершение после одного файла.

Паскалевская часть невелика и читается целиком. Существенную часть объёма
занимают runtime, файловая библиотека, растровый шрифт и буферы.
Следующий шаг для полной декомпиляции — восстановить 451 слово приложения
и отдельно воспроизвести внешнюю крупную печать и используемые варианты
библиотек. Целостность поведения и совпадение после сборки здесь ещё не проверены.
