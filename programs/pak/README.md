# ПАК: восстановление по машинному образу

Перенесено из репозитория re-pak (коммит 1851630).

**Обе редакции восстановлены побайтово.** Редакция 2113 описана
[ниже](#редакция-2113). Для редакции 2053/2048/2248: четыре зоны, 24576 байт,
4096 слов. Пересборка совпадает с тремя копиями на 2053/2048/2248,
включая загрузчик, код, константы, данные, библиотеку и хвост зон.
Прямое сравнение выполняет `compare-image.py`; результат —
[image-comparison.md](image-comparison.md).

`pak.pas` содержит все 29 подпрограмм и основной блок: 2692 слова
пользовательских тел (`02026–07231`). Ещё 19 слов генерирует компилятор
для входа, файловой инициализации и запуска. Историческая библиотека
восстановлена в Мадлене в `pak.pre`, загрузчик и отдельный сборочный
писатель — в `pak.loader.b6`.

Сборка проверена при временно недоступном `pak.bin`: эталон при ней
не читается, готовый бинарный файл не исправляется. Собранный образ
проверен также независимой командой `cmp`. Сам ПАК под исходной ОС
ДИСПАК пока не запускался.

## Где найдено

По каталогам томов в репозитории besm6.github.io:

| Каталог | Том | Зоны, восьмеричные |
|---|---:|---|
| `besm6.github.io/wiki/2053-contents.md` | 2053 | `0437–0442` |
| `besm6.github.io/wiki/2048-contents.md` | 2048 | `0034–0037` |
| `besm6.github.io/wiki/2248-contents.md` | 2248 | `3044–3047` |

Все три извлечённых образа совпали: 24576 байт, четыре зоны по 1024
48-битных слова. SHA-256:

```
2bbea399fc9b5eece7f9719ec56bb7a733d011af697dc975bc551fd38725c775
```

Это ПАК для В-111 из каталога D-2048. Копия ПАК с тома 2113
(`2113:1246–1251`) оказалась **другой редакцией**, поэтому
он не использован как эталон восстановления `pak.pas`; для него
теперь восстановлен отдельный `pak-2113.pas`. В частности, его константы
начинаются с `07255`, а у извлечённой редакции — с `07237`.

Исходные тома не записываются. Бинарные образы не хранятся в Git:
`extract.py` извлекает и сверяет три копии в `build/pak/original/`
и кладёт рабочий эталон в `build/pak/pak.bin`. В Git хранится только
протокол `original/provenance.json`.

## Разметка образа

Все адреса ниже восьмеричные.

| Адреса | Содержимое |
|---|---|
| `02000–02011` | загрузчик PASCODER, включая данные и резерв |
| `02012` | установка M10=`07237`, переход к запуску |
| `02013–02025` | инициализация OUTPUT и рабочего текстового файла |
| `02026–05720` | пользовательские подпрограммы, включая вложенные |
| `05721–07231` | основной блок |
| `07232–07236` | запуск Pascal и вызов инициализации файлов |
| `07237–10117` | константы, строки |
| `10120` | база P/1D, M1 |
| `10174` | рабочий текстовый файл IO |
| `10677` | OUTPUT |
| `10735` | PASZERO*, символ заполнения чисел |
| `10736–11546` | библиотека Pascal |

`pak.sym` именует подпрограммы и найденные библиотечные входы;
`build/pak/pak.dis` — дизассемблер с этой таблицей (см. «Повторение»). Имена пользовательских процедур
и переменных преимущественно придуманы при восстановлении: PMD-таблиц
с исходными именами в образе нет. Имя рабочего файла `БУФБ` восстановлено
из константы `2710502` в его инициализаторе (кодировка TEXT-Дубна);
в раннем дизассемблировании он обозначен `IO`. `PASZERO*` соответствует имени библиотечного common;
его имя задано режимом `S1` в списке параметров программы, после него
восстановлен `S0` для внешних процедур без звёздочек.

## Компилятор и проверенный исходник

Пробная компиляция и восстановленные процедуры проверены на штатном
`*PASCAL`: листинг сообщает `PASCAL COMPILER 15.0 (15.02.82)`.
Проверенные тела воспроизводятся без изменений компилятора. Это сильное
свидетельство совместимости с этим генератором, но не доказательство
точной даты исторического транслятора.

NEWPASC с установленного тома 77 также проверялся на небольшом примере.
Он иначе размещает инициализацию файлов и иначе компилирует `div 8`.
Опция `o-` штатным *PASCAL отвергается; она в `pak.pas` не используется.

В `pak.pas` восстановлены:

- `02026–04407`: перестройка очередей `relink`, чтение слов ОС через Э65,
  форматирование, дата и время, признаки устройств, заголовок отчёта и подробная печать паспорта задачи;
- `04410–04637`: список томов по классам и номера свободных установок;
- `04640–05073`: состояние каналов и устройств, признаки использования тома;
- `05074–05421`: дата, время, режимы ЭВМ, буферы и свободные ресурсы;
- `05422–05564`: линейка разрядов и распределение банков памяти;
- `05565–05720`: обход очередей по классам, печать и обновление паспортов;
- `05721–07231`: снимок состояния ОС, выбор и последовательность отчётов,
  распределение каналов, статистика очередей, устройства и рабочая память.

У всех 29 подпрограмм и основного блока совпадают длины и полные
последовательности команд
после разрешения перемещённых адресов. Сравнение проверяет реальные
значения констант и байты строк, адреса переходов внутри процедур,
смещения глобальных и локальных переменных, имена вызываемых процедур
и библиотечных входов. Оно не отбрасывает вставленные команды и не
принимает совпадение отдельных фрагментов за совпадение процедуры.

Восстановленная `task` (`03334–04407`, 556 слов) печатает идентификатор и
имя задачи, список требуемых томов, причину задержки, бюджетные признаки,
время и параметры памяти. Вложенные `mark`, `volume`, `volist`
(`03144–03333`, 120 слов) учитывают статистику и форматируют тома.
Восстановлена упаковка трёх 16-битных описателей томов в одно слово;
подпрограмма также уплотняет список недоступных томов в паспорте.
Числовые имена полей `nAxB` обозначают B разрядов с позиции A от старшего
разряда. Смысл части полей и исходные имена пока неизвестны.

`pak.pre` включает четырёхсловную внешнюю процедуру `DECODEID`
(`11260–11263`): вызов Э50/104 для преобразования идентификатора в имя.
В том же файле восстановлен двухсловный вход Э53/10 (`11364–11365`),
получающий текущее время; ему дано имя `SYSTIME`. Все шесть слов этих
двух процедур совпали с оригиналом без нормализации. Сборщик
ассемблирует файл в частную библиотеку; проверка сверяет обе процедуры
автоматически.

Основной блок использует конструктор неупакованной записи `[0C]` в
режиме `Y+` для совместного обнуления упакованных счётчиков. Рассылка
`END.DATA` восстановлена из исходного образа: проверка сравнивает без
нормализации ячейки M1:`050–053` и `112–556`. Она включает указатели
на таблицы ОС, флаги, шаблоны строк и нулевые рабочие области. Блок
файла `БУФБ` инициализирует сам компилятор.

В `pak.pre` также восстановлены `SAVEMASK` (Э62/131 и Э50/131),
`SETBYTE` (Э62/124 с упаковкой аргументов) и `SETBANK` (Э72).
Проверяются команды и встроенные константы; внутренние ссылки
разрешаются с учётом размещения объектов.

Пул `07237–10117` совпадает побитно. Общий заголовок каналов вынесен
в строковую константу; порядок типов записей и матрицы сохраняет порядок
коэффициентов 8, 32 и 47 в пуле. Библиотечный участок `10736–11546`
(393 слова) также совпадает побитно.

`recover-runtime.py` повторяет извлечение библиотеки в Мадлен из
эталона. Эта операция нужна только для регенерации исходника. Обычная
сборка ассемблирует сохранённый `pak.pre` в частный PERSO `3777/0100`.
Три группы `PAKRT1–3` организованы при восстановлении; исходные границы
объектных модулей не установлены.

`pak.loader.b6` содержит исходный шестисловный `P/BOOT` и новый
`PAKWRITE`, работающий только при сборке. `PAKWRITE` находится ниже
`02000`, за пределами сохраняемого образа. Он сохраняет исторические
поля загрузчика (чтение с `33/0000`, стек `01520`, четыре зоны), а
записывает образ на частный том `3777` через `67/0315`. Конечная страница
проверяется перед записью. ПАК и его библиотечные процедуры при сборке
не вызываются. Проверка запуском в исходной ОС ДИСПАК ещё не выполнена.

В READSYS сохранены исходные BESM-вставки с номерами ячеек кадра.
Штатный транслятор принимает одну команду на вызов `besm` и выравнивает
каждую такую вставку до слова. Переставлять локальные переменные этой
процедуры без повторного сравнения нельзя.

## Повторение

Нужны `dispak`, `besmtool`, Perl, Python 3 и инструменты проекта:
`py/libmatch.py`, `tools/disbesm6`, `tools/dtran` (`make -C tools disbesm6 dtran`)
и `tools/decomp.pl`. Команды выполняются из корня проекта.
Образы томов доступны по обычному пути BESM6_PATH; проверялись системные
2053/2048/2248 и системные тома 2113/77/2148-440.

```sh
python3 programs/pak/extract.py
tools/disbesm6 -b -a2000 -e2000 -nprograms/pak/pak.sym build/pak/pak.bin > build/pak/pak.dis
python3 programs/pak/lift.py
python3 programs/pak/build.py pak.pas --compiler pascal
python3 programs/pak/compare-prefix.py
python3 programs/pak/compare-image.py
cmp build/pak/pak.bin build/pak/pak-pascal/image.bin
```

Сборка использует штатный `*PASCAL`, частный HOME и частный том 3777 внутри
`build/pak/pak-pascal`. Результаты: `image.bin`, `listing.txt`, `job.b6` там же,
`build/pak/prefix-comparison.json` и `build/pak/full-image-comparison.json`.
Библиотечная сборка имеет отдельные `runtime-job.b6` и
`runtime-listing.txt`. При ошибке старый image.bin удаляется.
Выгружается число зон, указанное в `P/CODER+2`; оно не обрезается
фиксированным пределом выгрузки.
Сравнение по умолчанию включает весь основной блок, служебный вход,
инициализацию файлов, запуск, внешние процедуры и начальные данные.
`--routines-only` исключает основной блок, `--main-end=6144` проверяет
только его начальный участок до указанного восьмеричного адреса.
`routines.txt` и `globals.txt` — входные словари старого декомпилятора;
их числовые смещения глобальных переменных десятичные.

Дальнейшая работа — уточнение имён полей и испытание на снимке
исходного окружения ОС.

## Редакция 2113

`pak-2113.pas` восстановлен по четырём зонам `2113:1246–1251`.
Они извлекаются в `build/pak/pak-2113.bin`.
Все 24576 байт пересборки совпали с эталоном, включая загрузчик,
константы, DATA, библиотеку и нулевой хвост:
[2113-image-comparison.md](2113-image-comparison.md).
SHA-256: `a1392bfba7e529ab4f15cd11453eb0c37bcb07e633059445611aa585f365aa2b`.

```sh
python3 programs/pak/extract.py --edition 2113
python3 programs/pak/build.py pak-2113.pas --compiler newpasc \
  --compiler-source compiler/mypas.b6 --compiler-profile pak-2113
python3 programs/pak/compare-prefix.py --edition 2113
python3 programs/pak/compare-image.py --edition 2113
cmp build/pak/pak-2113.bin build/pak/pak-2113-newpasc/image.bin
```

`extract.py --edition 2113` повторяет извлечение и обновляет
`original/2113-provenance.json`. Бинарные файлы игнорируются Git.
`pak-2113.sym` содержит разметку (дизассемблирование — как для `pak.sym`);
`pak-2113.pre` — восстановленную библиотеку, `pak-2113.loader.b6` —
загрузчик и сборочный писатель. Библиотека сгруппирована в четыре
перемещаемых объекта; исходные границы архивных объектов не установлены.
При сборке эталон не читается и готовый образ не исправляется.

| Адреса, восьмеричные | Содержимое |
|---|---|
| `02000–02011` | загрузчик, привязка чтения `67/0000` |
| `02012` | вход |
| `02013–05674` | 29 пользовательских подпрограмм |
| `05675–05707` | инициализация файлов |
| `05710–07247` | основной блок |
| `07250–07254` | запуск Pascal |
| `07255–10135` | константы и строки |
| `10136–10751` | данные и файлы; IO=`10212`, OUTPUT=`10713` |
| `10752–11562` | библиотека |

От предыдущей редакции отличаются запросы к монитору и снимок системы:
161 слово вместо 164, упакованные четырёхбитные значения каналов,
дополнительные маски ресурсов и каналов. Проверка готовности задачи
учитывает пересечение маски доступных каналов с каналами её класса.
Добавлен список физических барабанов; число выводимых банков определяется
маской ресурсов. Банки с номером больше 37 получают полную маску.
DATA сохраняет шестисимвольные строки и обычные целые для `64…C`.

Для воспроизведения использован NEWPASC из `compiler/mypas.b6`.
Скрипт собирает его на частной копии тома 77 внутри `build/pak` и проверяет,
что установленный том не изменился. Профиль `pak-2113` меняет одну ветвь
генератора `CARD`: вместо `ACX 0; AEX 9(M1)` выдаёт эквивалентную
инструкцию эталона `ACX 9(M1)`. Исходный `mypas.b6` остаётся неизменным;
хеши исходного и адаптированного текста пишутся в протокол сборки.
Проверенная версия зафиксирована в `original/2113-compiler.json`.
`O-` сохраняет повторные чтения, локальный `W+` воспроизводит булевы
выражения и конструкторы множеств. Совпадение пересборки с эталоном
подтверждает восстановленный код; конкретный исторический компилятор,
которым собрана эта редакция, пока не установлен. Сам ПАК под исходной
ОС ДИСПАК не запускался.
